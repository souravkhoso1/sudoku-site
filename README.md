# Daily Sudoku

A tiny, static, GitHub Pages–only sudoku site. No backend, no build step, no
frameworks. One new puzzle a day, generated by a scheduled GitHub Action and
committed straight into the repo as JSON.

## How it works

- **Puzzles live in `/puzzles/YYYY-MM-DD.json`.** Each file has the puzzle
  grid, the solution grid, and a difficulty label. `/puzzles/manifest.json`
  lists every date that's available so the front end knows what to fetch.
- **`scripts/sudoku-core.js`** generates a full valid grid and carves cells
  out of it one at a time, backing off any removal that would create a
  second solution — every puzzle has exactly one solution. Generation is
  seeded from the date string, so regenerating a given date always produces
  the same puzzle.
- **`.github/workflows/daily-puzzle.yml`** runs every night at 00:05 UTC,
  generates the day's puzzle (plus a 2-day buffer, so a missed run doesn't
  leave the site without a puzzle), and commits the new file(s).
- **`index.html` / `css/style.css` / `js/app.js`** are the site itself —
  plain HTML/CSS/JS, no dependencies, nothing to build.
- **Progress is saved in `localStorage`**, keyed by puzzle date, so it
  survives a page reload but never leaves the visitor's device. This
  replaces "cookies" from the original brief — same result (progress is
  remembered locally), just without cookie size limits or expiry.

## Setting it up

1. Create a new GitHub repository and push the contents of this folder to
   it (either as the repo root for a `username.github.io` user site, or as
   a normal repo for a project page).
2. In the repo, go to **Settings → Pages** and set the source to
   **Deploy from a branch**, branch `main`, folder `/ (root)`.
3. Go to **Settings → Actions → General** and make sure "Workflow
   permissions" is set to **Read and write permissions** — the daily job
   needs to push commits.
4. The repo already ships with 15 pre-generated puzzles
   (2026-08-01 through 2026-08-15) so the site works immediately. After
   that, the scheduled Action takes over. You can also trigger it manually
   any time from the **Actions** tab (`Generate daily sudoku puzzle` →
   **Run workflow**).

## Generating puzzles locally

```bash
# Today's puzzle only
node scripts/generate-daily-puzzle.js

# A specific date
node scripts/generate-daily-puzzle.js 2026-09-01

# Bootstrap a bunch of days at once (e.g. the next 30)
node scripts/generate-daily-puzzle.js --days-ahead 30
```

Each run also rewrites `puzzles/manifest.json` to include any new files.

## Notes / things you might want to tweak

- **Difficulty rotation** is day-of-week based (see `difficultyForDate` in
  `scripts/sudoku-core.js`) — easy early week, medium Thu/Fri, hard on
  weekends. Change the clue counts in `DIFFICULTY_CLUES` or the rotation
  logic to taste.
- **Timezones**: the site picks "today" based on the visitor's local date,
  falling back to the most recent available puzzle if today's hasn't been
  generated yet (e.g. a visitor far ahead of UTC just after midnight). This
  means visitors in different timezones may occasionally see the puzzle
  "roll over" at slightly different real-world times — there's no
  server, so this is the tradeoff for keeping the site fully static.
- **Mistake limit** is 3, defined as `MISTAKE_LIMIT` in `js/app.js`.
- **Certificate download** draws a PNG on a hidden `<canvas>` and triggers
  a browser download — no server round-trip.
